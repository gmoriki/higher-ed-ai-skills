# ai-tone-check

大学業務文書のドラフトを、業務文書適切性、AI 臭度、読者負荷の 3 軸で点検する。AI エージェントは、本文を読む前に公開範囲と機密情報の有無を確認し、指摘、修正案、残リスクを返す。

## いつ使うか

- 広報原稿、Web 掲載文、SNS 投稿、プレスリリースを公開前に確認したい時。
- 職員研修、SD 研修、新任研修の配布資料を確認したい時。
- 学生向け FAQ、窓口案内、履修ガイドの読みやすさを確認したい時。
- AI で下書きした文面を、大学職員が書いた自然な文面に寄せたい時。

使わない場面:

- 規程本文、契約書、法的文書の条文調整。
- 学術論文、研究報告、査読文書。
- Level 2/3 情報を含む文書を、入力可否確認なしにレビューする場面。

## 入力前の確認

本文を読む前に、次を確認する。

- 文書種別: 広報、学生向け案内、職員向け通知、研修資料など。
- 読者: 職員、学生、学外者、受験生、保護者。
- 公開範囲: 公開、学内限定、部局限定、個別配布。
- 含まれそうな情報: 学生、教職員、人事、研究、入試、未公表情報。
- 目的: 公開前確認、配布前確認、文体修正、読者負荷確認。

Level 2/3 が含まれる可能性がある場合は、本文を読む前に `check-info-level` で事前トリアージする。

## 評価軸

| 軸 | 見るもの |
|---|---|
| 業務文書適切性 | 大学公式利用に耐えるか、過度な口語・宣伝調・軽口がないか |
| AI 臭度 | 冗長敬語、空虚な強調、無意味な両論併記、一般論の締めがないか |
| 読者負荷 | 1 文の長さ、専門用語、主語省略、段落のつながり、スマートフォンでの読みやすさ |

## 手順

1. 入力前の確認を行う。
2. 読者ロールを `staff`、`student`、`public` から選ぶ。指定がなければ `public`。
3. 文書を読み、3 軸で 0-10 点を付ける。
4. 重大な事実確認、誤解、差別的表現、読者不利益を先に指摘する。
5. 指摘 Top 5 と修正優先度を返す。
6. subagent dispatch が使える場合は独立レビュアーを使う。使えない場合は、単一エージェント評価であることを明示する。

## 出力フォーマット

```markdown
## Tone Check 結果

**対象:** <文書名または直接テキスト>
**読者:** <staff / student / public>
**公開範囲:** <公開 / 学内限定 / 不明>

## スコア
- 業務文書適切性: X/10
- AI 臭度: X/10
- 読者負荷: X/10

## 指摘 Top 5
1. <該当箇所> -> <問題> -> <修正案>

## 修正優先度
1. <最優先>
2. <次点>

## 残リスク
- <事実確認、承認、機密情報など>
```

## 落とし穴

| 合理化 | 実態 |
|---|---|
| AI っぽさだけ直せばよい | 大学文書では事実確認、承認、読者不利益の方が優先される |
| 丁寧にすれば大学らしい | 冗長敬語は読者負荷を上げる。短く正確な文の方がよい |
| 学生向けだから柔らかくすればよい | 重要な手続きは、親しみやすさより誤解の少なさを優先する |
| subagent が使えないので自分でロールプレイすれば同じ | 独立評価ではない。単一評価として限界を明示する |
| 公開予定文書だから何でも読ませてよい | 公開前の人事、研究成果、学生実名が含まれることがある |
