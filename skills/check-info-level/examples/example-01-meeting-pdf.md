# 例 1: 教授会資料 PDF の入力前トリアージ

## 入力

```text
教授会資料 PDF を要約したいです。
本文やファイルはまだ渡しません。

資料カテゴリ:
- 教授会資料
- 議題に通常報告、次年度カリキュラム案、人事案件が混ざる可能性あり
- 出席教員の発言記録が含まれる可能性あり
- 外部公開予定なし
- 利用予定環境は契約済み Team 版。学習利用、保存期間、削除手順は未確認

本文を読まずに、入力可否の事前トリアージをしてください。
追加で必要な情報があれば、本文ではなく情報カテゴリで質問してください。
```

## skill の処理

1. 事前トリアージとして扱い、PDF 本文もファイルメタデータも開かない。
2. 資料種別、公開範囲、含まれそうな情報カテゴリ、処理目的、AI 実行環境だけで暫定判定する。
3. 人事案件と発言記録が含まれる可能性を Level 3 リスクとして扱う。
4. 議題単位で切り分ける前提を置き、全文要約は避ける。
5. 内容判定へ進む条件と、追加で必要な情報カテゴリを返す。

## 期待される出力

```markdown
## モード
事前トリアージ

## 判定
暫定 Level 3

## 根拠
- 資料種別: 教授会資料
- 情報カテゴリ: 人事案件、出席教員の発言記録、未確定のカリキュラム案を含む可能性
- 判断に使った記述または前提: 本文やファイルは未確認。資料カテゴリと含まれそうな情報だけで暫定判定

## AI 入力可否
全文入力は不可。議題単位で人事案件・個別発言記録を除外し、残部を再判定する。

## 推奨次アクション
1. 議題一覧だけで、通常報告、カリキュラム案、人事案件、学生個別案件の有無を分類する。
2. 人事案件、採用・昇任、評価、懲戒、個別学生に関する箇所は AI 入力対象から外す。
3. 残部についても、発言者名、個人名、未確定事項を含むか確認する。
4. 契約済み Team 版の学習利用、保存期間、削除手順、管理者ログの扱いを情報基盤部門に確認する。
5. 内容判定が必要な場合は、読む範囲を議題単位で最小化し、事前に確認先の承認を得る。

## 最終確認先
- 議長または委員会事務局
- 情報基盤部門
- 人事案件を含む場合は人事担当または権限者

## 残リスク
- PDF の本文を開いていないため、個別学生、人事、未公表研究、発言者名の混入有無は未確認
- PDF メタデータに作成者名、更新者名、コメント履歴が残る可能性
- 議題名だけでは Level 2/3 の境界が判断できない場合がある
```

## なぜこの応答が適切か

- 入力可否を判断するために、いきなり PDF 本文を読んでいない。
- 「教授会資料」というカテゴリと、人事案件・発言記録の可能性だけで暫定 Level 3 としている。
- 内容判定へ進む条件を、議題単位の最小読取、契約条件確認、権限者確認に分けている。
- ファイル本文だけでなく、PDF メタデータのリスクも残リスクとして扱っている。
