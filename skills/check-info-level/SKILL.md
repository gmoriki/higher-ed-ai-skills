# check-info-level

AI エージェントが、大学業務資料の入力可否を事前トリアージし、必要な場合だけ内容確認後の Level 判定を返す。本文を読むこと自体が問題になるケースを前提に、事前トリアージと内容判定を分けて実行する。

## いつ使うか

- 本文やファイルを渡す前に、AI 入力可否の事前トリアージをしたい時。
- 資料種別、情報カテゴリ、AI 実行環境だけで、入力可否の見立てを出したい時。
- ユーザーが明示的にファイルや本文を読み、Level 1/2/3 判定を返すよう依頼した時。
- 議事録、申請書、学生データ、研究ノート、広報文を AI で処理する前段。

使わない場面:

- 所属大学の独自判定フローで既に判断できる場合。
- Office バイナリを完全解析する必要がある場合。本 skill は簡易判定であり、必要なら専用ツールでメタデータ除去を行う。
- 法的判断や処分判断が必要な場合。

## 入力前の確認

最初に、ユーザーの依頼がどちらかを判定する。

1. **事前トリアージ**: 本文やファイルを読まず、資料カテゴリだけで判断する。
2. **内容判定**: ユーザーが明示的に本文やファイルを読ませ、Level 判定を求めている。

事前トリアージではファイルを開かない。足りない情報があれば、本文ではなく次のカテゴリで質問する。

- 資料種別
- 公開範囲
- 含まれそうな情報カテゴリ
- 処理目的
- AI 実行環境
- 所属大学の関連規程の有無

内容判定へ進む条件:

- ユーザーが内容確認を明示している。
- 現在の AI 環境でそのファイルを読むことが適切である。
- 必要最小限の範囲だけ読む方針が示せる。

## 判定軸

| 観点 | Level 1 | Level 2 | Level 3 |
|---|---|---|---|
| 公開範囲 | 公開済み | 学内・部局限定 | 個人・審査・機密 |
| 学生情報 | なし | 集計済み | 氏名、学籍番号、成績、相談記録 |
| 教職員情報 | 公開プロフィール | 役職や内部連絡 | 人事、評価、懲戒、発言記録 |
| 意思決定 | 公開済み | 検討中 | 人事、入試、処分など重大決定 |
| 研究 | 公表済み | 未公表の一般構想 | 未発表データ、共同研究秘密、倫理審査対象 |
| 入試・試験 | 過去公開分 | 一般説明 | 未公開問題、採点、選抜資料 |

複数 Level が混在する場合は最も高い Level を採用する。内容を読まない事前トリアージでは「暫定 Level」として出す。

## 手順

1. 事前トリアージか内容判定かを明示する。
2. 事前トリアージなら、本文やファイルを開かず、カテゴリ情報だけで暫定 Level と追加質問を返す。
3. 内容判定なら、読む範囲を最小化し、必要に応じてファイル種別とメタデータの有無を確認する。
4. `confidential-info-guidelines` の Level 1/2/3 に照らして判定する。
5. AI 入力可否、条件、匿名化・切り出し・人手対応への切替を提示する。
6. 所属大学での最終確認先を返す。

## 出力フォーマット

```markdown
## モード
<事前トリアージ / 内容判定>

## 判定
<暫定 Level 1/2/3 または Level 1/2/3>

## 根拠
- 資料種別:
- 情報カテゴリ:
- 判断に使った記述または前提:

## AI 入力可否
<そのまま可 / 条件付き / 入力しない / 匿名化後に再判定>

## 推奨次アクション
1. <追加確認>
2. <匿名化・切り出し・契約確認・人手対応>

## 最終確認先
- <担当部署 / 委員会 / 決裁権者>

## 残リスク
- <未確認事項>
```

## 落とし穴

| 合理化 | 実態 |
|---|---|
| 判定するためにまずファイルを開くしかない | 入力可否の判断では、資料カテゴリだけで先にトリアージできる |
| Level 2 だから無料 Web 版でもよい | Level 2 は契約、保存、学習利用、削除手順を確認した環境が前提 |
| Level 3 でも一部だけ見ればよい | 一部閲覧でも AI 環境に機密が渡る可能性がある。読む範囲と権限確認が必要 |
| 必ず Level を断定する方が親切 | 事前情報だけなら暫定 Level と追加質問を返す方が実務に合う |
| ファイル名だけなら安全 | ファイル名に学生名、人事案件、研究テーマが含まれる場合がある |
