# 例 1: 「研究費執行管理」業務を unified protocol の SKILL.md にする

## 入力

```text
/create-action-skill
```

## skill 内対話の流れ

**skill**: 「どの大学業務を skill 化しますか。本文や内部規程はまだ貼らず、業務名、利用者、判断軸、出力したいものをカテゴリで教えてください。」

**user**: 「科研費、機関配分研究費、民間助成金それぞれで、購入物の分類、年度末発注期限、出張費精算の判断基準が違う。担当者が迷わず判断できるように整理したい。」

**skill**: 「ユーザーがどんな言葉で相談した時に起動すべきですか。」

**user**: 「『この物品は備品？消耗品？』『年度末の発注期限は？』『この出張は科研費から出せる？』」

**skill**: 「本文や内部規程を読む前に確認すべき情報カテゴリは何ですか。」

**user**: 「資金種別、購入物の単価、研究目的との関係、発注時期、所属大学の会計規程。」

**skill**: 「AI が返すべき出力は何ですか。」

**user**: 「判定、根拠、確認すべき規程、事前相談先、年度末なら期限リスク。」

**skill**: 「よくある落とし穴は何ですか。」

**user**: 「設備備品と消耗品の境界、直接経費と間接経費の混同、年度末の発注遅れ。」

**skill**: 「配置先はどこにしますか。」

**user**: 「研究支援領域に置きたい。」

**skill**: 「`domain-skills/research-support/grant-fund-execution-rules/` に unified protocol 形式で生成します。作成してよいですか。」

## 生成されるファイル

- `domain-skills/research-support/grant-fund-execution-rules/SKILL.md`
- `domain-skills/research-support/grant-fund-execution-rules/examples/example-01-equipment-vs-supplies.md`

## 生成された SKILL.md frontmatter 抜粋

```yaml
---
name: grant-fund-execution-rules
description: >
  研究支援職員や研究者が「この物品は備品か消耗品か」「年度末の発注期限に
  間に合うか」「この出張を科研費から支出できるか」と相談した時に使う。
  資金種別、物品種別、単価、発注時期、研究目的との関係、所属大学規程を確認し、
  判定、根拠、確認先、残リスクを返す。
license: CC BY-SA 4.0
metadata:
  version: "1.0.0"
  last_updated: "2026-05-10"
  author: gmoriki
---
```

## 生成された SKILL.md 本体の骨子

```markdown
# grant-fund-execution-rules

研究費執行の判断を、資金種別、物品種別、単価、発注時期、研究目的との関係で整理する。

## いつ使うか

- 物品が備品か消耗品か迷う時。
- 年度末発注や納品期限が問題になる時。
- 出張費や謝金をどの資金から支出できるか確認したい時。

使わない場面:
- 所属大学の会計担当が既に明確な判断を出している場合。

## 入力前の確認

- 資金種別
- 物品・支出種別
- 単価
- 発注時期
- 研究目的との関係
- 所属大学の会計規程

## 判断軸

| 資金種別 | 消耗品 | 設備備品 | 中間価格帯 |
|---|---|---|---|
| 科研費 | 直接経費で執行可能な場合がある | 設備備品手続を確認 | 機関判断 |

## 出力フォーマット

## 判定
<執行可 / 要事前相談 / 不可 / 要規程確認>

## 根拠
- 資金種別:
- 支出種別:
- 金額:
- 時期:

## 確認先
- <研究支援課 / 経理課 / 研究代表者>

## 残リスク
- <納品時期、規程差、証憑不足>

## 落とし穴

| 合理化 | 実態 |
|---|---|
| 研究に使うなら科研費で出せる | 研究目的との関係、規程、証憑が必要 |
```

## なぜこの生成プロセスが適切か

- 旧 Reference / Task 二分類を使わず、すべて unified protocol として生成している。
- 内部規程や実データをいきなり貼らせず、まず情報カテゴリを確認している。
- 出力フォーマットを先に決めるため、AI エージェントが返すものがぶれにくい。
- 落とし穴を明示し、現場で起こる合理化を抑止している。
- ファイル作成前に配置先と作成ファイルを明示し、ユーザー承認を取っている。
