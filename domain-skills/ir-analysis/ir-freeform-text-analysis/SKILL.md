# ir-freeform-text-analysis

学生調査・授業評価・自己点検評価の自由記述を、匿名化、カテゴリ抽出、検証、報告の流れで扱う。AI エージェントは、生データを読む前に入力可否を確認し、分析手順と検証観点を返す。

## いつ使うか

- 学生アンケートや授業評価の自由記述を分類したい時。
- 大学評価、内部質保証、SD 活動報告などの記述データを整理したい時。
- AI を使ったカテゴリ抽出、クラスタリング、報告書下書きを検討する時。
- 匿名化済みデータを使える AI 環境を判断したい時。

使わない場面:

- 生の学生データを外部 AI にそのまま入力する場面。
- 個別学生への介入、中退予測、学業予警の判断を行う場面。本 skill では自由記述分析まで扱う。
- 研究倫理審査や同意手続を省略する場面。

## 入力前の確認

自由記述本文や CSV を読む前に確認する。

- データ種別: 授業評価、学生調査、入学時調査、SD 報告、自己点検資料。
- 個人情報: 氏名、学籍番号、教員名、科目名、所属ゼミ、相談内容。
- 同意と利用目的: 授業改善、内部質保証、研究利用、公開資料。
- サンプルサイズと属性: 学年、学部、性別、国籍など。
- AI 環境: 契約済み環境、API、学内閉域、ローカル。
- 報告範囲: 学内、部局、教員個別、公開。

生データを読む必要がある場合でも、まず匿名化・属性粒度・利用環境を確認する。

## 分析手順

1. データ利用目的と同意範囲を確認する。
2. 氏名、学籍番号、教員名、科目名、固有の出来事を削除・置換する。
3. 属性の組合せで再特定されないよう粒度を落とす。
4. 小さなサンプルでカテゴリ案を作る。
5. 職員がカテゴリ妥当性を確認する。
6. 全体データへ適用し、件数、代表例、例外を整理する。
7. 報告書では個人が推測される引用を避ける。

詳細な工程は [`references/workflow-steps.md`](references/workflow-steps.md) を参照。

## AI 環境の考え方

| データ状態 | 扱い |
|---|---|
| 生データ | 原則 AI に渡さない。学内閉域やローカルでも規程確認が必要 |
| 匿名化途中 | AI 入力前に職員が確認する |
| 匿名化済み | 契約済み環境またはローカルで分析。Web 版は慎重に扱う |
| 公開済み集計 | 通常利用しやすいが、引用の再特定に注意 |

## 落とし穴

| 合理化 | 実態 |
|---|---|
| 氏名を消せば匿名化 | 学部、学年、科目、記述内容の組合せで再特定される |
| 匿名化後なら無料 Web 版でよい | 大学の規程や契約条件次第。業務データは慎重に扱う |
| AI のカテゴリ分類をそのまま報告できる | サンプル目視検証とカテゴリの再調整が必要 |
| 代表コメントを載せれば説得力が出る | 少数属性や固有表現から個人が推測されることがある |
| 自由記述分析と中退予測は同じ | 予測・介入はリスクが高く、別 skill と倫理審査が必要 |
